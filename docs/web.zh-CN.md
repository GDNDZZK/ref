`ref-web` 在浏览器中显示 ref。它是一个小型 Web 服务器：提供页面、用密钥为浏览器登录，解密浏览器的 WebSocket 帧后原样转发给 `ref-server`（反方向同理）。会话、工具和权限都留在后端，所以同一个会话可以同时在终端和浏览器标签页中打开。与 `ref` 一样，`ref-web` 通过 instance 文件找到运行中的后端，没有时启动同目录的 `ref-server`；这样启动的后端会在最后一个客户端断开后退出。

## 启动

```bash
ref-web                       # 监听 127.0.0.1（随机端口）并打开浏览器
ref-web ~/src/project         # 新会话在此目录启动
ref-web --port 8080 --no-open # 固定端口，不打开浏览器
```

不带 `--port` 时，`ref-web` 在 10000–65535 中随机选一个空闲端口，并记在 `<state 目录>/web/port` 里，下次启动先试这个端口，所以只要它空闲，地址就不变；被占用时会重新选一个并记下。`--port N` 使用该端口，被其他程序占用时报错退出。

全部选项见[命令行](cli.zh-CN.md#ref-web)。页面把你传入的目录作为新会话的目录；没有传入时使用 `ref-web` 的启动目录。`ref-web` 打印的地址用 `?dir=` 传递这个目录；地址栏还可以带 `?session=<id>`（打开该会话）和 `?view=split`（分屏视图），并随你切换的会话而变化。

## 登录

启动时，`ref-web` 会打印一个带密钥的地址并在浏览器中打开：

```
http://127.0.0.1:<端口>/?dir=/home/you/src/project#key=…
```

密钥在 `#` 之后的部分（fragment）。浏览器从不把 fragment 发给服务器，所以密钥不会出现在任何请求、`Referer` 头或日志里。页面读取密钥，把它从地址栏移除，然后登录。没有 cookie，也没有登录路由。

**密钥。** 不带 `--key` 时，密钥就是登录 token：64 位十六进制字符，首次启动时生成，保存在 `<state 目录>/web/login-token`（权限 600；Unix 上发现权限更宽时会改回并提示）。文件内容不是这种格式时，`ref-web` 报错 *does not hold a valid login token* 并退出。`--key KEY` 或环境变量 `REF_WEB_KEY` 为本次运行指定密钥，至少 16 个字符，不会写入磁盘，此时既不读取也不创建 token 文件。写在命令行上的密钥会出现在进程列表和 shell 历史中，`REF_WEB_KEY` 可以让它不出现在进程列表里。默认密钥随机且足够长，建议使用它。

**页面如何登录。** 密钥本身从不传输。页面打开 WebSocket 时，`ref-web` 发送一个新的随机数和一个 salt；页面回复自己的随机数和一个由密钥算出的证明，双方再由密钥和这两个随机数推导出本次连接专用的密钥。此后双向的每条消息都经过加密和认证（XChaCha20-Poly1305）。录下的连接无法再次登录，因为下一次连接使用新的随机数。salt 是 `<state 目录>/web/salt` 中的 16 个随机字节（权限 600），它不是秘密。

**地址形式。** 页面从三种地址形式中读取密钥：

| 形式 | 会发给服务器吗？ | 用途 |
|---|---|---|
| `#key=K` | 不会 | `ref-web` 打印并打开的地址 |
| `?key=K` | 会，在请求行里 | 需要把密钥放在查询参数里的链接 |
| `?token=K` | 会 | 旧名称；旧的 `/login?token=…&dir=…` 书签也仍然可用，它们会打开页面 |

查询参数里的密钥会以明文暴露：页面通过网络上的普通 `http://` 提供时，路径上的任何人都能看到；反向代理及其访问日志能看到（nginx 默认记录查询参数）；页面移除它之前，浏览器历史里也有。当密钥出现在另一台机器上普通 `http://` 页面的查询参数里时，页面会显示提示。所有响应都带 `Referrer-Policy: no-referrer`。

**浏览器保存什么。** 页面不保存密钥本身，而是把经 scrypt 拉伸后的密钥连同 salt 保存在 `localStorage` 的 `ref.web.key` 下，只对这个地址（协议、主机和端口）有效。有了它，每次刷新和重连都会自动登录。能读取浏览器配置文件的人，或在页面中运行的脚本，都能用这个值登录，直到密钥更换。页面的 Content-Security-Policy 只运行页面自带的脚本文件，模型输出按文本显示。没有 `localStorage`（某些隐私模式）时，页面把它保存在内存里，刷新后会再次询问。

**输入密钥页面。** 页面没有密钥、保存的密钥是用另一个 salt 生成的、或 `ref-web` 拒绝了密钥时，页面显示“输入密钥”，带一个密码框和“登录”按钮。页面拉伸密钥时显示“正在检查密钥…”（在手机上最多约一秒）；密钥错误时显示“密钥未被接受。”。需要密钥期间，页面不会自行重连。

**重启与更换密钥。** `ref-web` 重启后密钥和 salt 不变，已打开的页面会重连并保持登录。要更换密钥，先停止 `ref-web`，删除 `<state 目录>/web/login-token`，再重新启动；使用 `--key` 时，用另一个密钥启动即可。之后每个浏览器都会显示输入密钥页面，用 `ref-web` 新打印的地址即可重新登录。删除 `<state 目录>/web/salt` 也会让每个浏览器重新询问密钥。

## 查找已运行的实例

每个运行中的 `ref-web` 都会在 `<state 目录>/web/instances/<pid>.json` 写一条记录（pid、端口、host、tls、版本和启动时间；不含密钥；权限 600），停止时删除。再次启动 `ref-web` 时会按从新到旧的顺序查看这些记录；如果某条属于密钥相同的 `ref-web`，就打印该实例的地址（带本次的 `DIR` 和密钥；若启用了 TLS，先打印 `certificate SHA-256` 指纹），打开浏览器，并以退出码 0 退出。带 `--port N` 时只看该端口上的实例。已运行的实例保持它自己的 `--server`、`--mock`、`--host` 和 `--no-tls`，第二次启动的这些选项不生效，并会有提示。`ref-web` 靠 `/api/ping` 的应答识别自己的实例，应答用由密钥推导出的密钥签名（记录为 `tls: true` 时通过固定证书的 TLS 连接探测）；`/api/ping` 只应答本机的调用者。对应进程已不存在的记录会被删除。

没有匹配的实例时，启动一个新的。带 `--port N` 时，如果记录中该端口上是密钥不同的 `ref-web`，启动会报错 *a ref-web with a different key is running on port N (pid P); stop it, or pass the same --key*；端口被其他程序（或另一个 state 目录的 `ref-web`）占用时报错 *port N is in use by another program or by a ref-web with a different key*。两者都以退出码 1 退出。同时发生的两次启动可能各自启动一个实例，这无害。

## 向局域网开放

`ref-web` 默认只监听 `127.0.0.1`（普通 `http://`，无证书警告）。`--host ADDR` 可以监听其他地址，例如 `--host 0.0.0.0` 向局域网开放，此时**默认启用 HTTPS**，使用保存在 `<state 目录>/web/tls/` 的自签名证书，并打印警告。

- **首次访问。** 浏览器不认识自签名证书，首次打开该地址（`https://…`）时会警告连接不是私密连接（例如 Chrome/Edge：*你的连接不是私密连接* → *高级* → *继续前往*；Firefox：*警告：存在潜在的安全风险* → *高级…* → *接受风险并继续*；Safari：*此连接非私人连接* → *显示详细信息* → *访问此网站*）。继续之前，请核对 `ref-web` 打印的指纹（`ref-web: certificate SHA-256 …`）与浏览器中显示的证书指纹是否一致；一致再继续，指纹不同则不要继续，说明有别的服务在回答该地址。在 TLS 端口上用 `http://` 访问会自动重定向（`308`）到 `https://`（不保留路径和查询参数）。
- **地址与证书名称。** 证书包含 `localhost`、`127.0.0.1`、`::1` 以及 `--host`（对于 `0.0.0.0` 或 `::`，会附带本机的主出站 IPv4 地址，若存在）。请打开 `ref-web` 打印的地址（`https://<地址>:<端口>/`）；用其他地址访问会在证书机构警告之外多出名称不匹配的提示。用其他主机名访问会被拒绝：`ref-web` 会用已知地址校验 `Host` 头，以防范 DNS rebinding。证书在到期前 30 天内或 `--host` 新增名称时会自动重新生成。
- **`--no-tls` 与反向代理。** `--no-tls` 让非回环 `--host` 使用普通 `http://`（在回环地址上是无提示的空操作）。此时消息仍用密钥加密，但页面和它的脚本以明文传输，路径上的人可以篡改页面并窃取密钥（见[已知限制](#已知限制)）。请仅在终结 TLS 的反向代理后使用 `--no-tls`，或让 `ref-web` 只监听回环地址并配合 SSH 隧道或 nginx：

  ```bash
  # SSH 隧道：在服务器上运行 `ref-web --no-open --port 7480`
  ssh -L 7480:127.0.0.1:7480 server
  # 然后在本机打开 http://127.0.0.1:7480/
  ```

  ```nginx
  # nginx 放在 `ref-web --no-open --port 7480` 前面（将 Host 和 Origin 改写为回环地址）
  location / {
      proxy_pass http://127.0.0.1:7480;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
      proxy_set_header Host 127.0.0.1:7480;
      proxy_set_header Origin http://127.0.0.1:7480;
  }
  ```

要使用在别处运行的后端，传入 `--server ws://host:port --token T`（见[在另一台机器上运行后端](cli.zh-CN.md#在另一台机器上运行后端)）。`--token` 必须与 `--server` 一起使用，`--server` 不能与 `--mock` 同时使用。
## 使用页面

页面与[桌面 GUI](gui.zh-CN.md)是同一套界面。本节列出页面有什么、与 GUI 有何不同；对话的详细说明见 GUI 一页，工具卡片、权限、图片、撤销和压缩的外观与行为相同。下文的按钮和命令名称取自简体中文界面。

**窗口**

- 左边的侧边栏最上面是当前会话（分屏视图中是获得焦点的分块）的待办清单，标题为“待办 已完成/总数”，下面是各项；该会话没有清单时这一栏不出现，清单超过侧边栏的三分之一高度后在栏内滚动。再往下是运行中的会话、带搜索框的历史、MCP 服务器的状态和设置。可以隐藏（Alt+B），状态会被记住。窗口窄于 800 px 时，侧边栏变成覆盖在内容上的抽屉，且没有分屏视图。
- 运行中的会话优先显示名字，没有则显示标题，再没有则显示目录名。历史中的会话优先显示标题（压成一行），没有则显示名字，再没有则显示目录名，与终端界面一致。*运行中*列表随行数增高，只有在*历史*会少于三行时才出现滚动。
- *新建会话*在页面所用的目录里新建会话。要在其他目录新建，用旁边的文件夹按钮或命令*在其他文件夹新建会话…*（没有快捷键）。它会询问路径；按 Tab 或点击可补全子目录，子目录由后端列出。
- 命令面板（Ctrl+P，macOS 上 Cmd+P）可运行任何命令。不带参数的命令直接运行；重命名、更改目录、导出、变体、关闭指定会话和对等名称会先询问参数。输入框的 `/` 列表显示同一份命令，包括自定义命令。
- 关闭最后一个会话时，会在同一目录新建一个，页面不会空。没有 `/editor` 和 `/exit`。`/compact` 不再确认。
- 后端比页面旧时，顶部出现横幅和*重启后端*按钮。有运行中或等待授权的会话时按钮不可用。重启会停止后端，页面自动重连，`ref-web` 会启动已安装的新版后端。
- 你没有在看的会话（以及分屏视图中的任何会话）出错时，右上角弹出“会话名: 错误首行”。最多同时显示 4 条，info、警告、错误分别停留 3.5、6、8 秒；鼠标悬停暂停计时，相同的消息再次出现时重新计时而不叠加。当前会话的错误显示在对话末尾。

**分屏视图**

- Alt+W 或右上角的按钮为每个后台会话显示一个分块：没有其他客户端打开的存活会话，加上当前会话。点击分块或按 Alt+方向键移动焦点；命令作用于获得焦点的分块。用 Alt+Z 或分块上的按钮放大分块，此时按钮显示*返回分屏视图*。
- 只有获得焦点的分块显示输入框。其他分块把输入框（连同标签行和附件条）收起，只保留状态行（状态、已用时间、上下文用量）和排队等待的消息。草稿文本、附件、shell 模式和光标位置都会保留；分块获得焦点时输入框展开，光标落在其中。放大的分块照常显示输入框。

**对话**

- Alt+R 展开/折叠全部思考块，Alt+O 展开/折叠全部工具详情；点击块头只改变这一块。`todo` 调用的待办清单不可折叠。等待授权的卡片始终展开。
- bash、read、grep 的输出最多显示 200 行，其余有*显示其余 N 行*。仍在运行的 bash 调用显示最后 20 行。卡片宽度不小于 560 px 时，还显示调用用时。
- 消息下方：作者、时间和 token；*复制*（该消息的文本），你自己的消息上还有*撤销*。Alt+Y 复制最后一条回复，Alt+U 撤销上一条提示并把它放回输入框。
- 滚动到靠近顶部（约 400 px）时，更早的消息会自动加载且视图不跳动；点击*加载更早的消息*效果相同。
- 会话有待办清单时，它的状态行（分屏视图的每个分块也一样）会像终端界面那样显示正在做的那一项（没有则是第一个待办项）和 *已完成/总数*，已取消的项两个数字都不计。全部完成后显示对勾和绿色的 *已完成/总数*。点击它会在弹出框里打开完整清单（按 Esc、点击别处或切换会话时关闭）；清单打开时会实时更新。
- 授权键：获得焦点的会话（分屏视图中只限获得焦点或被放大的分块）有待授权请求时，a 或 Enter 允许一次，s 本会话内允许，d 或 Esc 拒绝。请求出现 350 毫秒后按键才生效，焦点移到有请求的分块后也会重新等待 350 毫秒；之后在请求答完之前，其他字母键不会输入到输入框。打开的对话框保留自己的按键。其他分块里的请求，用它卡片上的按钮回答，或先让该分块获得焦点。
- 图片显示为缩略图，点击后放大查看，Esc 关闭。链接只对 http、https 和 mailto 打开；模型 Markdown 里的图片显示为链接，HTML 按文字显示，所以对话本身不会引发任何网络请求。

**模型的提问**

模型调用 `question` 工具时，问题显示在这次调用的卡片里，卡片会为此展开。在你回答之前，卡片、侧边栏里该会话的行和状态行都显示“等待你的回答”（页面语言为英文时是 *Waiting for your answer*），该会话的分块标题也像等待授权时那样高亮。

- 每个问题有简短的标题、问题本身和若干选项，每个选项有名称和说明。模型推荐的选项已被预先选中，并标有*（默认）*。只有一个问题且为单选时，一次操作就回答：点击、数字键 1 到 9，或在高亮的行上按 Enter（光标从默认项开始）。
- 有多个问题，或问题允许多选时，每个问题一个标签页，最后一个标签页是*确认*。单选题选定后会跳到下一个标签页；多选题用复选框，推荐的选项已勾选，按 → 或 Tab 跳到下一个标签页。*确认*页列出各个回答，把没有动过的问题标为*未回答*。点*提交*或按 Enter 发送；未回答的问题按“未回答”发送。
- 模型允许时，最后一行是*输入自己的答案*。选中它会出现文本框：Enter 接受文本（空文本不算），Esc 离开文本框。多选题里，文本会加到已勾选的选项之后。
- 点*忽略*或按 Esc 忽略这些问题；模型会被告知你没有回答。
- 按键（与终端界面和 GUI 相同）：↑、↓ 或 k、j 移动光标（到第一行和最后一行为止），1 到 9、空格或 Enter 选择该行（多选题是切换复选框），←、→、Tab 和 Shift+Tab 切换标签页（有标签页时），在*确认*页按 Enter 提交，Esc 忽略。这些键与授权键的规则相同：等待 350 毫秒后才生效，问题等待回答期间其他字母键不会输入到输入框，文本框保留自己的按键，在分屏视图中只对获得焦点或被放大的分块有效。其他分块里的问题，用它卡片上的按钮和选项回答，或先让该分块获得焦点。
- 问题先在另一个窗口被回答时，它的卡片会直接消失，没有提示。后端拒绝了你的回答时，右上角会显示它的消息，卡片保留。

**输入框**

| 按键 | 作用 |
|---|---|
| Enter | 发送。会话忙时，提示在队列中等待；*撤回*可以取回。 |
| Shift+Enter、Ctrl+J | 换行。 |
| Tab、Shift+Tab | 下一个或上一个智能体。打开 `/` 或 `@` 列表时，Tab 是补全。 |
| Alt+T | 下一个模型变体（Ctrl+T 被浏览器占用）。 |
| Esc、Esc | 中断正在进行的一轮（1.5 秒内按第二次）。第一次 Esc 会先关闭已打开的列表、退出 shell 模式，或者在有工具调用正在等待延迟时，在该工具运行之前停止这一轮。 |
| ↑、↓ | 提示历史：输入框为空或光标在文本开头时按 ↑ 进入，浏览中在第一行继续 ↑；浏览中在最后一行按 ↓ 往后翻。 |
| Ctrl+C | 没有选区时清空输入框；有选区时是复制。 |
| 行首输入 `!` | shell 模式：这一行作为 shell 命令运行。输入框为空时按 Backspace 或按 Esc 退出该模式。 |

- 可以粘贴剪贴板中的图片，或把图片文件拖放到输入框（PNG、JPEG、GIF 或 WebP，单张不超过 20 MiB）。文本中会有 `[Image N]` 令牌，与终端界面相同。浏览器无法粘贴文件的路径或 `file://` 地址。
- `@` 列出会话目录下的文件，选中后插入 `@路径 `。
- 提示历史（500 条）保存在浏览器里（`localStorage`，键为 `ref.promptHistory`），不与终端界面或 GUI 共用。

## 通知

当你没有在看的会话需要工具权限、向你提问、结束一轮或以错误结束一轮时，页面可以显示系统通知。屏幕上正在看的会话不会通知。点击通知会打开对应的会话。正文是“等待授权使用 {工具}”、“提问：{问题}”（第一个问题）、“已完成”或“因错误而停止：{错误}”（页面语言为英文时是 *Waiting for permission to use {tool}*、*Asks: {question}*、*Finished*、*Stopped with an error: {error}*）。

- 需要浏览器允许。页面顶部的提示条会问一次（*允许*或*暂不*；选了*暂不*会记在 `localStorage` 里），设置里有同样的按钮。
- 浏览器只在 `localhost`、`127.0.0.1` 和 `https` 页面显示通知。通过局域网中的普通 `http` 地址访问，或浏览器禁止了通知时，只有标签页标题和标签页图标会提示需要处理。
- 设置里有总开关和三个分类：会话在等你（授权或提问）、一轮对话结束、一轮对话出错结束。默认全部打开。

## 设置

按 Alt+S 或点侧边栏里的设置按钮打开：主题（跟随系统、亮色或暗色）、语言（跟随系统、English 或 简体中文）和通知。设置保存在浏览器里（`localStorage`，键为 `ref.settings`，其中也包括侧边栏是否显示），同一浏览器的各个标签页共享。已保存的设置里有错误的值时，该值改用默认值，其余保留。

## 连接

- `ref-web` 每 30 秒向每个标签页的 WebSocket 发一次 ping。某个标签页 60 秒内没有任何帧（既没有 pong，也没有普通消息），或者因为浏览器不读取而 60 秒内发不出一帧时，该标签页的连接及其到后端的连接都会被关闭。因此笔记本休眠或断网后，后端不会留下失效的会话订阅。
- 连接断开时，页面会自动重连，并用保存的密钥重新登录。`ref-web` 拒绝密钥时（关闭码 4401，例如密钥更换之后），页面停止重试并显示输入密钥页面（见[登录](#登录)）。`ref-web` 没有运行时，页面会一直重试。
- `ref-web` 的其他关闭码：4400 表示登录消息格式错误或消息无法解密，4408 表示 10 秒内没有完成登录，1011 *backend unavailable* 表示连不上后端（详情在 `ref-web` 的日志里）。

## 已知限制

- 通知需要 `localhost` 或 `https`（见上）。
- 有些浏览器把 Alt+←/→ 用作后退和前进。用 Alt+方向键移动分块焦点，还没有在所有浏览器里试过。
- 某些键盘布局下，Alt+字母会产生特殊字符；页面按物理按键匹配，不看产生的字符。
- 提示历史和设置按浏览器保存，不与终端界面或 GUI 共用。
- 工具的参数和输出按 UTF-8 文本显示。

密钥及其加密防不住以下情况：

- **能篡改页面的人。** 通过网络上的普通 `http://` 访问时（`--no-tls`，或上游这一段没有 TLS），路径上的人可以提供一个被改过的页面，其脚本在你输入密钥时读取它，或读取保存的值。加密无法阻止这一点，因为负责加密的代码也来自同一个连接。使用 `ref-web` 自身的自签名 TLS 时，除非你在首次访问时核对了 SHA-256 指纹（首次信任），否则同样存在此风险。在不可信的网络上，请使用 SSH 隧道，或带正式证书的反向代理。
- **流量分析。** 消息的大小和时间是可见的；没有 TLS 时，路径、`Host` 头以及正在使用 `ref-web` 这一事实也可见。
- **两端本身。** 能读取 `ref-web` 的 state 目录或浏览器配置文件的人就拥有密钥。用 `--key` 给出的密钥在那台机器的进程列表和 shell 历史中可见。
- **到后端的一段。** `ref-web` 与 `ref-server` 之间是普通的 `ws://`。在同一台机器上它只走回环地址；使用 `--server ws://remote` 时会经过网络。
- **把密钥输进别人的页面。**

## 开发页面

页面在 `web/` 中（Vue 3、TypeScript、Vite、pnpm）。`ref-web` 嵌入构建后的文件，构建方法见[开发](development.zh-CN.md#构建)。在构建 `ref-web`，或用 `--workspace` 运行 `cargo build`、`cargo test`、`cargo clippy` 之前，要先在 `web/` 中运行 `pnpm install && pnpm build`，否则 `build.rs` 会报错。

```bash
cd web
pnpm install
pnpm dev                  # Vite 开发服务器，127.0.0.1:5173
```

`pnpm dev` 把 `/ws` 和 `/api` 转发到 `127.0.0.1:7480` 上的 `ref-web`（`REF_WEB_URL` 可指定其他地址，包括指向启用 TLS 的 `ref-web` 的 `https://…`——代理会接受其自签名证书）。先启动 `ref-web --no-open --port 7480`（或 `ref-web --mock --no-open --port 7480`），再用 `ref-web` 打印的地址中的密钥打开 `http://127.0.0.1:5173/#key=…`。页面会为开发服务器的地址保存密钥。全程使用 `127.0.0.1` 而不是 `localhost`：保存的密钥只属于一个地址。直接连接 `ref-server` 的开发构建（`VITE_REF_URL`）不使用密钥，也不加密。
